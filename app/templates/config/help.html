Pipeline overview

Configure everything under Pipeline as a chain per source:

Source → Events → Rules → Actions

  1. Source — a webhook receiver or a poll that fetches a URL on a schedule.
  2. Events — named event types for that source (e.g. payment.paid, on_success).
  3. Rules — which events (and optional field conditions) should fire actions.
  4. Actions — update a Field, send an HTTP request, or push a browser notification when the rule matches.

Typical setup: add a source, define event types, create a rule for those types, then add actions on the rule. Confirm results on Events.

Fields

Fields are shared values on the Pipeline page (not tied to one source). Actions write into them; dashboard widgets read them. They are separate from condition keys on event payloads.

TypePurpose
logbook Append-only list of JSON entries with a max size. Good for recent activity.
counter Numeric tally — a field push can increment, decrement (default by 1), or reset.
value A single string.
toggle On/off state.

Create Fields first, then pick one on a field_push action and on widgets under Dashboard Layout (Series Graph, Chart, or Display modes such as Logbook list, Stat, and Toggle).

Rule matching

When an event arrives, enabled rules are checked in Order Index order. A rule matches only if all of these pass:

  1. Source — the rule belongs to that event’s source (rules are set up per source on the Pipeline page).
  2. Event types — leave the list empty to match all types for that source; otherwise the event’s type must be selected.
  3. Conditions — see below; with no conditions, every event that passed the filters above matches.

Then each linked enabled action on the rule runs.

Rule conditions

Conditions filter on fields in the event data (the JSON body from a webhook, or values extracted from a poll). In the rule dialog you build rows of Field + Operator + Value. Use Edit as JSON when you need a shape the visual editor does not express.

Behavior

  • Empty (no rows) — match all events that already passed source and event-type filters.
  • All must match — every condition row has to pass.
  • Missing or invalid data — for most operators, a missing field, a bad number, or an invalid pattern means the condition does not match. The not operator is the exception: it also matches when the field is missing.
  • Nested fields — use a simple name like severity, or a dotted path like _poll.outcome / _poll.response_time_ms.

Operators

OperatorMeaningJSON example
equals Exact match (numbers are compared as numbers when the value looks numeric) {"severity": "high"}
not Not equal — matches when the value differs, including if the field is missing {"status": {"not": "ok"}}
gt Greater than (numeric) {"amount": {"gt": 10}}
lt Less than (numeric) {"amount": {"lt": 100}}
contains Substring appears in the text form of the value {"msg": {"contains": "error"}}
regex Matches a pattern in the text form of the value {"code": {"regex": "^5\\d\\d$"}}

Combining conditions

Multiple rows on different fields all must match. On the same field, gt and lt together form a range: 

{"amount": {"gt": 10, "lt": 100}, "currency": "USD"}

Prefer one clear operator per field in the visual editor. Use Edit as JSON for unusual shapes.

Examples

{}
# match all events for the selected types

{"severity": "high"}
# only when severity is exactly "high"

{"amount": {"gt": 100}, "currency": "USD"}
# amount > 100 AND currency equals USD

{"status": {"not": "ok"}}
# status is anything other than "ok" (including missing)

{"status": {"contains": "fail"}, "code": {"regex": "^5\\d\\d$"}}
# status contains "fail" AND code looks like 5xx

Actions

Each action has a type and settings for that type. The Pipeline chain shows what it does (for example, which Field it updates).

TypeWhat it does
field_push Writes to a Field (append, set, count, or toggle). Event keys and counter amounts can use dotted paths (e.g. _poll.response_time_ms).
http_forward Calls a URL (GET/POST/PUT/PATCH) with optional Bearer or Key+Secret credentials.
web_push Sends a browser notification. Title, body, and url can use {{ '{{source}}' }} / {{ '{{field}}' }} placeholders from the event.

Webhooks

Create a Webhook source, then send POST /webhook/{slug} with a JSON body.

  • Once the source has event types, you must send the type via the X-Event-Type header or a body field named event_type or type.
  • If you set a webhook secret on the source, also send X-Webhook-Timestamp (unix seconds) and X-Webhook-Signature — HMAC-SHA256 of {timestamp}.{raw_body}. Without a secret, unsigned requests are accepted (fine for local testing).

Each webhook event includes source (the source name) and a _webhook object with details such as slug, method, path, content_type, body_bytes, client, user_agent, event_type, correlation_id, signed, and delivery_lag_ms when a timestamp header was sent. Use these names in rule conditions or field pushes.

On the Pipeline page, use Recent on a source for the last few events, and Sample on an event type for that type’s latest payload (handy when writing rules and choosing field-push keys). Each source keeps at most 500 events; older ones are removed automatically.

Polling

Poll sources call a URL on a schedule (interval or cron) and feed the same pipeline. Set the schedule when you create or edit the source: method, URL, timeout, and optional retries.

A successful poll emits on_success (or another type you name in Handler Params as event_type). Failures emit on_failure. If you also add an event type named always, it fires on every run as well (it is not created for you automatically).

Each poll event includes source and a _poll object with schedule_id, status_code, attempts, outcome, and response_time_ms.

Optional Handler Params (JSON) can include json_path (which part of the response to keep), event_type, headers, query, body, and auth_secret_id for authenticated polls.

Web Push

To use web_push actions:

  1. Set PARA_SCOPE_VAPID_PUBLIC_KEY and PARA_SCOPE_VAPID_PRIVATE_KEY in your environment (optional PARA_SCOPE_VAPID_SUBJECT).
  2. While logged in, click the bell icon in the page header to allow notifications.
  3. In the action, use {{ '{{field}}' }} or {{ '{{nested.path}}' }} in title, body, or url to insert event values. Every event includes source (the Source name).

Secrets

On http_forward actions you can attach credentials (Bearer token or Key+Secret) in the action dialog. Values are stored encrypted. Webhook source secrets and poll auth secrets use the same store.
